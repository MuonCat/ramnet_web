The idea, in brief

Mainstream linear attention adds every token into one shared state, where their contributions interfere. Instead, RAM-Net splits the state into many slots. Each token's key selects a few slots to write, and its query selects a few slots to read.

  • Less interference. Each read or write accesses only the selected slots, not the entire state, so tokens interfere only when they select the same slots.
  • Scalable state. More slots add capacity, while the cost of each read or write stays constant.

01Motivation

Larger State, Sparser Access

The cost of history

A sequence model stores information from past tokens and retrieves the relevant part at every step. Its efficiency therefore depends on two costs, the amount of history it stores and the amount it accesses per step.

Full attention [1] keeps one key–value entry per token and compares each query against all of them, so both costs grow with sequence length. To mitigate this, KV compression and sparse attention reduce per-step access, but the cache typically keeps growing.

Instead, mainstream linear attention [2] compresses history into a fixed-size state. However, every step reads and writes the entire state. Consequently, all tokens interfere within the same state, and any increase in state size directly increases per-step access.

To address both issues, RAM-Net divides this fixed-size state into many addressable slots, and each step reads and writes only a few selected ones. Therefore, tokens interfere only when they select the same slots, and the state can grow without increasing per-step access.

02Architecture

Reading and Writing a Few Slots

Inside RAM-Net

RAM-Net organizes its fixed-size state as an array of |𝒜| independent slots. Each slot stores a vector and has an integer address a ∈ 𝒜 = {0, …, |𝒜| − 1}. Each token produces a key to select write slots, a query to select read slots, and a value to store.

Each step reads and writes only a few of these slots, in three stages:

  1. Address Decoder: maps the key and the query to sparse write and read addresses, which select a few slots and weight their contributions. It does so with a construction called Product Softmax. Each slot address a is written as U base-dp digits, so |𝒜| = dpU. The key is split into U sub-vectors of dp entries, and a softmax over each sub-vector gives the probabilities of one digit's values. A slot's weight is the product of its digit probabilities, and only the K highest-weight slots are kept as the write address. The query produces the read address in the same way. For visual clarity, the figure uses U = 5 and dp = 2, giving 25 = 32 slots, with K = 4.
  2. Cyclic Address Positional Embedding (CAPE): shifts these addresses according to token position, making addressing position-aware.
  3. Gated Sparse Update (GSU): writes the value into the selected write slots and leaves all other slots unchanged.

The selected read slots are then combined by their weights, normalized, gated, and projected to produce the output. Sections 3, 4, and 5 explain the three stages in detail.

Since each step accesses only the selected slots, the size of the state and the per-step access are set separately. The slot count |𝒜| sets the size of the state, while K sets how many slots each read or write accesses. Neither grows with sequence length, so storage and per-token cost stay constant as the context grows.

03Addressing

Efficient Sparse Addressing

Product Softmax

Section 2 showed how the Address Decoder obtains addresses with Product Softmax: it splits the key or query into distributions over a few digits and multiplies them to weight each slot. This section explains why addresses are built this way, and how the construction can be understood from several perspectives.

The direct approach would project the key and query to |𝒜| dimensions, apply a softmax over all slots, and keep the Top-K. This faces two obstacles. First, the projection and the softmax add parameters and computation that grow linearly with |𝒜|. Second, after Top-K truncation, only the K selected slots receive a learning signal at each step, so address selection becomes harder to optimize as |𝒜| grows.

Product Softmax resolves both. The slot count |𝒜| = dpU grows exponentially with the number of digits U, while the key and query dimension dk = U dp grows only linearly, so U dp scores suffice to address all |𝒜| slots. For example, RAM-Net uses |𝒜| = 1024 = 45 slots with only 20 scores. Moreover, each digit is shared by many slots, so the learning signal from a selected slot also reaches every slot that shares its digits.

The figure above shows how these digit distributions combine into a distribution over slots, from five equivalent perspectives.

Soft Radix Address

In base dp, each slot index is a sequence of U digits. Instead of fixing every digit to select a single slot, Product Softmax gives each digit a distribution over its dp values. Every slot is then weighted by the product of its digit probabilities.

Multilevel Decision Tree

Each digit forms one level of a tree, so every root-to-leaf path corresponds to one slot. A slot's weight is the product of the branch probabilities along its path. Since all nodes at a level share the same digit distribution, the most probable slots can be found level by level, at a cost that grows with the depth U rather than the number of leaves |𝒜|.

Joint Distribution

Each digit corresponds to one axis of a U-dimensional grid, so each slot is a grid point weighted by the product of its probabilities along every axis. A confident digit confines the weight to a slice of the grid, whereas an uncertain digit spreads it along its axis. Thus, the highest-weight slots lie where these slices intersect, extending only along the axes of uncertain digits. The figure illustrates the case U = dp = 4.

Regroupable Address

Since the weight is a product, any set of digits can be merged into a single coarser digit without changing any slot weight. Splitting the digits into two groups thus arranges the slots as a matrix whose weights form an outer product of two vectors. The figure shows two such groupings, 64 × 4 and 4 × 64, which trace different patterns over the same weights.

Waveform Modulation

Read along the slot index, each digit's distribution becomes a periodic step waveform. Low-order digits change at every slot and repeat quickly, whereas high-order digits change slowly and hold each value over long intervals. The address distribution is the product of these waveforms, with the slow ones setting a coarse envelope and the fast ones modulating it within.

All five views express one property, namely that a slot's weight factorizes into independent per-digit probabilities. This factorization enables an exact and efficient Top-K search. Following the tree, RAM-Net fixes the digits one level at a time and keeps only the K most probable partial addresses at each level. A dropped partial address already trails K others, and since all of them are multiplied by the same remaining digit probabilities, it can never overtake them. The search thus returns the exact Top-K while evaluating only K dp candidates per level, rather than all |𝒜| slots.

04CAPE

Position-Aware Addressing

Relative position

Product Softmax addresses slots by content alone, so identical content maps to the same slots at every position. Such addresses cannot tell where a token occurs relative to the current one.

Cyclic Address Positional Embedding (CAPE) adds this information by shifting each token's read and write addresses along the slot array according to its position. A read at step t then overlaps a write from step s according to their content and the distance t − s, rather than their absolute positions.

As a result, the same content written at different positions lands on different slots instead of overwriting the same ones. Since the slot array is finite, these shifts wrap around its end, which makes the embedding cyclic.

The shift only permutes slot indices, so each read and write still accesses K slots. RAM-Net applies CAPE to some heads and leaves the others content-only, without any positional shift. The CAPE heads capture relative-position patterns, whereas the content-only heads capture associations that hold regardless of distance.

05GSU

Balancing Retention and New Information

Updating slots

Each write must balance a selected slot's history against the incoming value, while leaving all other slots unchanged. Unlike the forgetting gates of mainstream linear attention, which decay the entire state at every step, Gated Sparse Update (GSU) forgets and writes only at the selected slots, so each slot is updated independently.

For each slot a, GSU keeps two quantities: its content st[a] and a write mass mt[a], which accumulates the write weights the slot has received. Given the write weight wt[a] and the incoming value vt, it updates them as follows, in computation order, which matches the four stages in the figure.

The four quantities form a chain: the content moves by a step size η, which depends on the write mass m, which in turn depends on the retention factor λ.

  • Content (s): moves toward vt by a step size ηt[a], covering that fraction of the remaining gap. A small η preserves history, whereas an η near 1 lets the new value dominate.
  • Step size (η): the write weight wt[a] relative to the updated mass, with a small ε for numerical stability. A stronger write takes a larger step, while more accumulated mass makes the step smaller, so a heavily written slot changes slowly.
  • Mass (m): retains a fraction λt[a] of its previous value and then adds the current write weight.
  • Retention (λ): decreases as the write weight grows, so a strongly written slot forgets more. It is further adjusted by the forgetting strength γt = xtWγ, computed from the current token by a learned projection; a larger γt keeps less of the previous mass.

As a result, GSU has three properties:

  1. Exact sparsity: for an unselected slot, wt[a] = 0 gives λt[a] = 1 and ηt[a] = 0, so both its content and mass stay unchanged. Writes from different tokens interact only at the slots they jointly address.
  2. Bounded content: since ηt[a] ∈ [0, 1), each update is a convex combination of the previous content and vt, so a slot stays on the scale of the values however often it is written.
  3. Adjustable forgetting: γt ranges the update between two extremes. As γt → −∞, λt[a] → 1 and the slot averages all past writes; as γt → +∞, λt[a] → 0 and ηt[a] ≈ 1, so each write nearly overwrites the slot.
A test-time training view. Following test-time training [3], each slot can be seen as a parameter trained online to fit the values written to it. The content update is exactly one gradient-descent step on the loss ℓt(s) = ½‖s − vt‖2, with learning rate ηt[a]. GSU thus performs per-slot test-time training: only the addressed slots are trained at each step, and each slot's learning rate decays as it accumulates writes, at a pace set by γt.
06Execution

Parallel Work Across Memory Slots

CUDA · Sparse access on the GPU

Sparse access reduces memory traffic. To turn that saving into efficient GPU execution, RAM-Net organizes work around independent memory slots.

During training and prefill, the model computes Top-K addresses across tokens in parallel, then groups read and write events by slot. Each slot receives its own sequence of access events.

Different slots and their channels can run in parallel, while events within each slot preserve the causal order required by the recurrence. Slots with no events require no work.

During autoregressive decoding, the model directly accesses the slots selected by the current token. It does not scan the full recurrent state.

Language Modeling and Reasoning — 340M and 1.3B models

RAM-Net achieves the lowest WikiText perplexity at both scales: 25.87 with Top-32 at 340M, and 15.90 with Top-16 at 1.3B, just below the 15.96 of Mamba2. Its commonsense reasoning remains competitive, with the highest average accuracy at 340M (50.9 for Top-32) and a tie with Mamba2 at 1.3B (57.8). Increasing Top-K consistently improves both perplexity and average accuracy, suggesting that accessing more slots per step strengthens language modeling.

Real-World Recall

Real-World Recall — 340M and 1.3B models

These recall-intensive tasks [10] require extracting information from real documents. Transformer++ achieves the highest average at both scales, since its KV cache keeps every context token. Among recurrent models, RAM-Net attains the highest average at both scales: 32.0 with Top-32 at 340M and 40.6 with Top-8 at 1.3B. At 340M, Top-8 accesses 0.4M of 26.2M state elements per step, about 1.5% of its total state. Even the largest settings, 340M Top-32 and 1.3B Top-16, access only 1.6M elements per step, at least 5× fewer than Gated DeltaNet and 8× fewer than Mamba2 at the same scale. The reduction carries over to practical speed: RAM-Net with Top-8 decodes faster than Mamba2 and Gated DeltaNet.

What changes with Top-K?

At 340M, moving from Top-8 to Top-32 increases active state from 0.4M to 1.6M elements while total state stays at 26.2M. Wiki. perplexity drops from 26.89 to 25.87, the S-NIAH average rises from 64.7 to 72.9, and the real-world recall average from 23.2 to 32.0. The trade-off is better results at a higher per-token access cost.

Beyond these tables

On the synthetic MQAR benchmark [11], RAM-Net lies on the upper envelope of accuracy against total state size, while accessing about 10× less state per step than baselines of comparable accuracy.

On a single NVIDIA RTX 5090, 340M RAM-Net with Top-8 matches the decoding throughput of GLA and exceeds Mamba2, DeltaNet [12], and Gated DeltaNet across all tested context lengths. The ranking follows per-step state access rather than total state size: GLA is fast because its whole state is small, whereas RAM-Net is fast because it accesses only a small part of a much larger state.

Retrieval still depends on reliable address selection: an unselected slot cannot contribute to the current read. More slots increase capacity; a larger Top-K increases access. Their benefits depend on the task.

11Hardware

Independent Slots, Local Execution

A hardware perspective · Decouple, schedule, reuse

RAM-Net suggests a natural front-end / back-end split. The front end computes projections and decodes sparse addresses into integers. It sends the selected slot IDs and their read or write payloads to the back end; the slot engines then work directly with addressed state.

Different slots have no state-update dependencies on one another. Each EU has two bounded queues; the back end chooses a queue dynamically from available capacity and cache locality, spreading distinct hot slots across EUs and queues while preferring to reuse local data. Stable hot chains keep queue affinity; sporadic events favor queues with less interference from existing chains. If a slot already has an outstanding request, subsequent requests must enter that same queue to preserve causality; it can rebind after those requests finish. When no eligible queue has room, backpressure holds the next event at the front-end outlet until space becomes available. Cache misses wait for DRAM while ready operations on other slots can execute first. This suggests an architecture between CPU and GPU styles: simpler dependency control than a general-purpose CPU, with more local scheduling freedom than a single lockstep GPU instruction stream.

The access concentration in the preceding section makes on-chip SRAM a promising home for frequently visited slots. Repeated reads and writes can stay near the execution units, so a small resident working set can absorb a large share of slot traffic. Consecutive operations on the same slot can retain state in EU registers, bypassing repeated SRAM communication. Register reuse is fastest, SRAM access takes longer, and DRAM fills or writebacks are much slower. Hot dirty entries are retained for reuse, with colder entries preferred for replacement. When eviction or migration is needed, dirty entries write back to DRAM after their operations finish; clean entries can be released directly. A new owner waits for any writeback before loading the slot. The sparse access footprint lets storage capacity grow independently of the number of operations issued per token.
